# Software Development Plan Creation Prompt

I need help developing a Software Development Plan (SDP) for a software project.

## About Software Development Plans

A Software Development Plan is a comprehensive document that outlines the approach, methodology, and structure for developing a software project. It follows industry best practices as outlined at: https://acqnotes.com/acqnote/careerfields/software-development-plan

The SDP should include these sections:

1. **Introduction** - Purpose, scope, objectives, assumptions/constraints, system overview
2. **Project Organization** - Structure, roles, documentation approach
3. **Development Milestones and Stages** - Deliverables and success criteria for each stage
4. **Resources** - Technical resources, environment, knowledge requirements
5. **Risk Management** - Identified risks and mitigation strategies
6. **Development Methodology** - Approach, cycle, coding standards, version control
7. **Quality Assurance** - Testing strategy, metrics, validation
8. **Configuration Management** - Version control, dependency management, data formats
9. **Project Monitoring and Control** - Progress tracking, quality monitoring, change management
10. **Documentation** - Code documentation, user documentation, inline documentation
11. **Definition of Terms** - Project-specific terminology
12. **Appendices** - Schemas, commands, workflows, and other reference materials

Note: Participant and timeline information is not desired. Do not include details about a leader, team, or labor distribution. Do not include dates and timeframes in relation to milestones.

## Terminology Preferences

- Use "stage" instead of "phase" for process steps
- Use "message" instead of "newsletter" for communication outputs
- Be specific and technical in all descriptions

## Collaboration Process

Before writing the full SDP, please:

### 1. Clarifying Questions
Ask about:
- **Project Purpose:** Core problems being solved and intended outcomes
- **Functionality:** Key features and capabilities
- **User Workflows:** Primary use cases and user interactions
- **Tech Stack Deviations:** Any changes from my standard preferences
- **Dependencies:** External systems, APIs, or libraries needed
- **Performance:** Expected scale, response times, or resource constraints
- **Security/Privacy:** Data sensitivity, access control, or compliance needs
- **Domain Specifics:** Industry requirements or specialized knowledge needed

### 2. Architecture Proposal
Once you understand the project, propose:
- High-level system architecture
- Component breakdown
- Data flow and storage approach
- Key technical decisions and rationale

### 3. SDP Development
After architecture approval, write the comprehensive SDP following the structure outlined above.
